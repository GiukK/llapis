# Provenance — how the shipped web-UI bundle was produced

**Nothing in this directory is applied, compiled or read by any build step.** Deleting it would
not change the product by one byte.

It exists for one reason: the bundle at `third_party/llama/tools/ui/dist` is a **build artifact**
— a SvelteKit bundle, minified, with content-hashed filenames — and it carries LLapis branding, so
it is not upstream's stock bundle either. Shipping 13 MB of opaque blob with no recorded source
would be wrong. This directory is that source.

The UI *source* delta is deliberately kept here rather than applied into `third_party/llama`. The
rule the release is built on is: *if the shipped launcher cannot reach it, it does not ship*.
Upstream's `scripts/ui-assets.cmake` takes the pre-built `tools/ui/dist` with priority 1 and then
`return()`s, and `LLAMA_BUILD_UI` is `OFF`, so `tools/ui/src/**` is never compiled in a user's
build. Putting those 32 files into the tree would add source that nothing reads and that a user
has no way to turn into the bundle they are already running.

## How the bundle was built

**This needs Node. That is the only place in the project that does.** A user building or running
LLapis never executes any of it.

```bash
# 1. a clean checkout of upstream at the pin, in a scratch directory -- NOT third_party/llama,
#    which already carries the LLapis runtime changes
git clone https://github.com/ggml-org/llama.cpp scratch-ui
cd scratch-ui && git checkout 050ee92d04c2e1f639025786dea701c70e7d4204

# 2. add the UI source delta on top
git apply --whitespace=nowarn ..\provenance\ui-source-050ee92d.patch
robocopy ..\provenance\new-files . /E

# 3. build the bundle
cd tools\ui
npm ci
npm run build          # = npm run build-pwa-assets && vite build  ->  tools/ui/dist
```

`npm run build` produces the 134 files of `tools/ui/dist`. It does **not** produce `dist/_gzip/`:
that parallel tree is written into the dist directory at CONFIGURE time by `emit_files()` in
upstream's `scripts/ui-assets.cmake` when `LLAMA_UI_GZIP` is `ON`, which is the setting this
project builds with. `_gzip/` is therefore derived, gitignored, and regenerated by every build.

To re-vendor: copy the 134 files of `tools/ui/dist` over `third_party/llama/tools/ui/dist`.
(Before 2026-08-10 the bundle was staged in a root `ui-dist/` and copied into place by
`scripts/bootstrap.ps1`; both are gone — the bundle now sits where the build reads it.)

## What this does and does not guarantee

It records **how** the bundle was made and **from what**. It does not promise a byte-identical
rebuild: npm dependency resolution, the PWA asset generator and vite's content hashes are not
pinned tightly enough for that, and no attempt was made to make them so. What a user receives is
now guaranteed by the repository itself — the bundle is committed, so `git status` is the check
that used to be `MANIFEST.sha256`.
